## 一、后端（aispring）优化建议

1. **配置与环境管理**
   - 建议统一使用环境变量驱动的配置方案（如 `SPRING_PROFILES_ACTIVE`、`APP_STORAGE_ROOT`），并在 `application-*.yml` 中只保留必要默认值，避免开发/生产环境分支过多导致配置漂移。
   - 将敏感配置（数据库密码、JWT 密钥等）统一放入环境或独立密钥管理系统，确保仓库中只出现占位符与示例配置。

2. **数据库与迁移**
   - 现有 Flyway 迁移脚本较多，后续可以：  
     - 定期对历史迁移进行归档与重整（如按大版本打快照），降低新环境初始化时的执行时间。  
     - 为关键表补充必要索引（如大表的查询条件字段），在上线前对慢 SQL 做一次集中分析。
   - 对高频写入表（如 Token 审计、AI 日志）考虑使用分表或保留周期（定期清理旧数据），避免历史数据无限增长影响性能。

3. **AI 调用链路与审计**
   - 已有 Token 审计与脱敏模块，建议：  
     - 统一在所有 AI 入口（同步/异步、SSE）前后插入相同的审计与脱敏拦截器，减少代码重复。  
     - 为审计表增加简单的聚合视图或物化视图，提供按天/按用户/按模型的统计，便于成本分析。
   - 根据调用量，适当增加请求重试与超时降级策略（如网络抖动时返回缓存结果或友好提示），提升稳定性。

4. **日志与监控**
   - 建议区分访问日志、业务日志与错误日志，对大量 DEBUG 级别日志进行收敛，避免生产日志过大。  
   - 可以统一接入 Prometheus/Grafana 或其他监控系统，对请求耗时、错误率、外部 AI 调用失败率等关键指标做可视化。

## 二、前端（vue-app）优化建议

1. **代码结构与模块划分**
   - 目前前端已拆分为多个视图与组件，建议进一步：  
     - 对 AI、云盘、word-game 集成等模块按领域划分子目录（如 `views/ai/*`、`views/storage/*`），减少根目录下文件数量。  
     - 将通用 UI 组件（按钮、弹窗、加载动画等）沉淀到 `components/common/`，统一样式与交互。

2. **状态与接口管理**
   - 使用 Pinia 作为统一状态管理已较合理，后续可以：  
     - 对所有 HTTP 请求封装统一的错误处理和认证失效逻辑，避免在各处重复 try/catch。  
     - 为核心模块的 store 补充分页缓存与乐观更新策略（如云盘、需求列表等），降低重复请求与界面闪烁。

3. **性能与体验**
   - 路由层面启用按需加载（动态 import 已存在），可以针对体积较大的视图（如需求分析、语言学习）进一步拆分子组件，避免一次性加载过多逻辑。  
   - 对 SSE 流式输出与长列表渲染场景，建议使用 requestAnimationFrame + 虚拟滚动（virtual scroll）减少 DOM 更新压力。

4. **样式与主题**
   - 深色/浅色主题已实现，后续可将颜色与间距系统化：  
     - 抽象出 Design Token（如 `--color-primary`, `--spacing-sm`），统一在 CSS 变量或 Tailwind/UnoCSS 配置中维护。  
     - 对表单、按钮、卡片类组件统一规范边距与圆角，减少局部样式覆盖带来的维护成本。

## 三、word-game 模块优化建议

1. **后端（Node/Express）**
   - 目前使用 better-sqlite3 同步操作数据库，简单可靠；在并发量明显上升时，可考虑：  
     - 将写操作集中在事务中批量提交，减少磁盘 IO 次数。  
     - 为进度与课程包相关查询增加覆盖索引（已存在部分索引，可按慢查询进一步优化）。
   - 对 JWT 校验与用户识别逻辑，可以与 aispring 共享一段「签名密钥获取 + 解析」工具，避免多处拷贝导致配置不一致。

2. **前端集成**
   - 当前通过 iframe 集成 word-game，主题与登录状态通过 postMessage 同步。后续可以：  
     - 约定统一的消息协议版本与类型枚举，避免前后端在扩展消息时出现不兼容。  
     - 为 iframe 加入健康检查与重试策略（例如自动检测 5200/5201 可用性，并在用户界面给出更友好的提示）。

## 五、后续演进方向（建议）

1. **服务拆分与边界稳定**
   - 保持 aispring 主站与 word-game 等子服务的边界清晰，可逐步向「后端网关 + 多服务」方向演进。  
   - 对于调用频率低、耦合度高的模块，可以先通过逻辑边界梳理，再考虑是否抽成独立服务。

2. **测试与质量保障**
   - 为关键模块补充集成测试：认证、云盘核心操作、word-game 进度保存、AI 需求分析流程等。  
   - 在前端增加基础的 e2e 测试（如 Playwright / Cypress），确保主流程（登录、上传、生成 PRD、使用 word-game）在重构后仍然稳定。

3. **自动化与发布流程**
   - 根据实际需求，可逐步引入 CI/CD：自动构建、单元/集成测试、镜像构建与部署脚本。  
   - 为生产环境配置滚动发布或蓝绿发布策略，减少升级对在线用户的影响。
